Theory Questions and Answers

Question

Compare UDP and TCP.

  • UDP: connectionless, datagram-oriented, unreliable, no ordering guarantee.
  • TCP: connection-oriented, stream-oriented, reliable, ordered, with flow and congestion control.
Question

Why can UDP datagrams arrive out of order?

IP packets may take different paths or experience different delays, and UDP does not reorder or retransmit. TCP numbers bytes and delivers them to the application in order.

Question

Explain the TCP three-way handshake.

  1. Client sends SYN with its initial sequence number.
  2. Server replies SYN-ACK with its own sequence number and acknowledgement of the client SYN.
  3. Client sends ACK.
  4. MSS may be announced as a TCP option during the SYN exchange.
Question

How do you compute MSS from MTU?

  • MSS: maximum TCP payload, not the full IP packet.
  • IPv4 without options on Ethernet: 1500 - 20 - 20 = 1460 B.
  • TCP options: subtract them if present.
  • IPv6 without extension headers: 1500 - 40 - 20 = 1440 B.
Question

Explain TCP teardown.

Each direction is closed independently with FIN and ACK. A common graceful close is FIN, ACK, FIN, ACK, though FINs can sometimes be combined with data/ACKs.

Question

Explain TCP congestion control.

  • The sender controls a congestion window to avoid overloading the network.
  • Slow start: increases quickly.
  • Congestion avoidance: increases more cautiously.
  • Packet loss: reduces the window.
  • Goal: network stability and fair sharing.
Question

Explain NAT/PAT.

NAT rewrites IP addresses; PAT additionally rewrites transport ports so many internal hosts can share one public IP. The NAT table maps internal tuple to external tuple and uses it to translate replies.

Question

Why is NAT harder for ICMP?

TCP/UDP have ports that identify flows. ICMP often lacks ports; error messages may include part of the original packet, so the NAT must inspect embedded headers to find the internal flow.

Question

Explain UDP hole punching.

  1. Both peers send outbound UDP packets so their NATs create mappings.
  2. A coordination server tells each peer the other peer's public endpoint.
  3. Incoming packets can then match existing NAT state.
Question

Recursive versus iterative DNS?

In a recursive query, the resolver is asked to obtain the final answer. In an iterative query, a server returns the best information it has, often a referral to another nameserver.

Question

DNS lookup roles?

  1. The stub resolver asks a recursive resolver.
  2. The recursive resolver queries root servers.
  3. It then queries TLD servers.
  4. It then queries authoritative nameservers until it obtains the requested record.
Question

Explain common DNS records.

  • A: maps name to IPv4.
  • AAAA: maps name to IPv6.
  • NS: delegates or identifies nameservers.
  • CNAME: aliases one name to another.
  • PTR: maps address to name in reverse DNS.
  • SOA: gives zone authority metadata.
  • MX: names mail exchangers.
Question

Reverse DNS for IPv4 and IPv6?

  • IPv4: reverses octets under in-addr.arpa.
  • IPv6: reverses hexadecimal nibbles under ip6.arpa.
  • Example: 203.0.113.4 becomes 4.113.0.203.in-addr.arpa.
Question

Which HTTP method loads a simple file/video?

Usually GET. It requests representation of the resource identified by the URL.

Question

Where does TLS fit and what do X.509 certificates prove?

TLS sits above TCP and below applications like HTTP; in OSI terms it provides session/presentation functions such as authentication, key agreement, encryption, and integrity. X.509 validation checks the certificate chain to a trusted root and that the requested domain is covered by the certificate.

Important Read

Reliability and Security Properties

Exam Nuance

TCP/UDP Checksums Are Not Security Integrity

Use this in the exam by first naming the goal, then saying which mechanism provides it. Example: TCP provides reliability through sequence numbers, ACKs, retransmissions, and ordered delivery. TLS provides confidentiality, integrity, and authenticity through cryptographic protection and certificates.

Protocol Reliability Confidentiality Integrity Authenticity
TCP Yes. Sequence numbers, ACKs, retransmissions, and ordered delivery repair lost or reordered data. No. TCP does not encrypt payload. No, for security. TCP checksum only detects accidental errors, not malicious manipulation. No. TCP does not prove who the peer is.
UDP No. No ACKs, retransmissions, ordering, or connection state. No. UDP payload is not encrypted. No, for security. UDP checksum only detects accidental corruption. No. UDP does not authenticate sender identity.
TLS No by itself. TLS relies on TCP or QUIC underneath for delivery. Yes. TLS encrypts application data. Yes. TLS detects tampering cryptographically. Yes. TLS uses certificates, usually X.509, to authenticate the server.
HTTP Only via lower layer. HTTP itself has no reliability; usually TCP below it provides reliable byte delivery. No. Plain HTTP is readable on the network. No. Plain HTTP can be modified by an attacker on path. No. Plain HTTP does not cryptographically prove server identity.
HTTPS Yes. Reliability comes from TCP or QUIC underneath. Yes. TLS encrypts HTTP data. Yes. TLS detects manipulation using cryptographic integrity protection. Yes. TLS certificates authenticate the server; sometimes client certificates are also used.
QUIC Yes. ACKs, retransmissions, streams, and ordering per stream. Yes. QUIC includes TLS 1.3 security. Yes. Cryptographic integrity via TLS/QUIC. Yes. TLS certificate authentication.
IPsec No, not normally. IPsec secures IP packets, but does not itself retransmit lost packets or guarantee ordering. Yes. ESP can encrypt IP payloads. Yes. IPsec can cryptographically protect packets against modification. Yes. Peers are authenticated using keys, certificates, or security associations.
  • TCP provides reliability, but not security.
  • TLS, QUIC, HTTPS, and IPsec provide security properties.
  • UDP and plain HTTP alone provide almost none of these security guarantees.
Useful combinations:
  • HTTP + TCP: reliable, not secure.
  • HTTP + TLS + TCP: HTTPS, reliable and secure.
  • HTTP + QUIC + UDP: HTTP/3, reliable and secure.
  • TCP + TLS: secure reliable channel.
  • UDP + QUIC: reliable secure transport.
  • IPsec + TCP/UDP: network-layer security underneath transport.
Best exam sentence: TCP gives reliability. TLS gives confidentiality, integrity, and authenticity. HTTPS combines HTTP with TLS, usually over TCP, so it gets both reliability and security. 
Checksum is not security integrity.
Do not say TCP/UDP provide integrity in a security sense.

Old Exams

Old Exam Questions and Answers

Endterm 2022, Aufgabe 3

Question: Compute TCP MSS over Ethernet/IPv4 and complete the TCP handshake.

Answer: MSS is MTU minus IPv4 and TCP headers/options; with Ethernet MTU 1500 and IPv4/TCP base headers it is 1460 B, or 1456 B if a 4 B MSS option is included in the segment under consideration. Handshake is SYN, SYN-ACK, ACK.

Endterm 2022, Aufgabe 6

Question: What happens with listen() on UDP and how many sockets does a TCP server need?

Answer: listen() makes sense for connection-oriented sockets, not UDP. A TCP server has a listening socket and a connected socket for each accepted client.

Endterm 2024, Aufgabe 3

Question: Chat messages arrive out of order; which transport protocol is likely?

Answer: UDP, because it does not guarantee ordering. TCP would deliver an ordered byte stream.

Endterm 2024, Aufgabe 5

Question: Download a video over HTTP/TCP/IPv6.

Answer: Use HTTP GET; TCP payload per full packet is MTU - 40 B IPv6 header -20 B TCP header when no options are present.

Endterm 2025, Aufgabe 1

Question: What must a browser check in an HTTPS X.509 certificate?

Answer: The certificate must chain to a trusted root and cover the requested domain. The private signing key is not inside the certificate.

Endterm 2025, Aufgabe 4

Question: Configure/understand DNS delegation to an authoritative nameserver.

Answer: Parent zone contains NS records delegating the child zone, and often glue A/AAAA records if needed to reach in-bailiwick nameservers.

Endterm 2025, Aufgabe 5

Question: Assign TLS to OSI layers and name functions.

Answer: TLS can be explained as session/presentation-layer functionality: session establishment/key agreement, authentication, encryption, and integrity protection above TCP.

Retake 2022, Aufgabe 5

Question: Fill a DNS zonefile.

Answer: Use SOA for zone metadata, NS for authoritative nameservers, A/AAAA for addresses, MX for mail, CNAME for aliases, and correct fully qualified names/trailing dots.

Retake 2022, Aufgabe 7

Question: Explain TCP Reno congestion control.

Answer: The sender adjusts congestion window; slow start grows quickly, congestion avoidance grows linearly, and loss reduces the window/threshold.

Retake 2023, Aufgabe 3

Question: Critique DNS resolution with recursive and iterative queries.

Answer: Stub to local resolver is usually recursive; resolver to root/TLD/authoritative servers is iterative, following NS referrals until the final RR is returned.

Retake 2025, Aufgabe 4

Question: Forward and reverse DNS with IPv6.

Answer: Forward names use A/AAAA. IPv6 reverse DNS reverses hexadecimal nibbles under ip6.arpa, and delegation occurs on nibble boundaries unless special mechanisms are used.

Retake 2025, Aufgabe 5

Question: IPv4, UDP, and NAT hole punching.

Answer: NAT maps private IP/port to public IP/port. Hole punching tries to create matching outbound NAT state at both ends so direct UDP packets are accepted.

Retake 2025, Aufgabe 6

Question: TCP congestion control under network problems.

Answer: Loss/timeout indicates congestion; the sender reduces its congestion window and then grows it according to slow start/congestion avoidance rules.

Exam Answer Checklist

Checklist

Exam Answer Checklist

  • UDP is datagram-oriented and connectionless; TCP is connection-oriented and stream-oriented.
  • TCP MSS is not the MTU: subtract IP header, TCP header, and TCP options if present.
  • NAT changes at least source or destination IP/port plus checksums; replies are mapped using the NAT table.
  • DNS recursive query asks the resolver to finish the lookup; iterative query returns the best referral or answer known by that server.
  • HTTPS certificate checks include a valid trust chain and that the requested domain is covered by the certificate.
